# xMustard v0.1.0

Released 2026-09-28. First tagged release, cut from `feat/parity-v2` at `9086dab`.
It carries wave 1 and most of wave 2 of the
[parity build plan](../plans/2026-09-25-parity-build-plan.md). Every workstream in it
was reviewed by one adversarial reviewer, fixed, and merged only after the full backend
suites passed on a Linux x86_64 build box.

**This is not a parity claim.** Numeric parity thresholds and the final parity-scale
gate arrive with WS-50. The parity-scale suite (4 agents, 2 hot repos, 4 worktrees)
still exceeds its 95.4 MiB line.

## What is in it

**MCP and transport**
- A dedicated MCP server package on protocol 2025-06-18, still nine tools.
- Streamable HTTP at `/mcp` on the API, plus `xmustard-relay`, a std-only stdio relay
  (about 2 MiB RSS, against about 14 MiB for the Go shim).
- Per-owner session quotas.
- `tools/list` stays under per-profile byte caps. Advanced arguments are accepted but not
  advertised; they are documented at `xmustard://docs/tools`.
- `ground` has an output budget (`sections`, `max_chars`) with a documented degradation
  ladder. Failure and stale signals are never dropped silently, and a recoverable
  original is kept.

**Storage and runtime**
- govstore, a SQLite (WAL) governance store. Governed memory is cut over to it, and legacy
  JSON stores are imported.
- A resident Rust worker with a Go supervisor.
- A budget governor with a heavy slot and health counters.
- The remaining JSON stores are locked and fsynced across processes.

**Code intelligence**
- `index.db` code index with streaming per-file extraction and bounded parsing.
- Language packs through one provider contract: Go, Rust, TypeScript/JavaScript, Python,
  Java, Kotlin, C, C++, C#, Swift, Ruby, PHP and Bash. Per-language coverage is reported in
  search, explain, impact and ground.
- A scope and import resolver for Go and TS/JS. It emits typed edges (CALLS, IMPORTS,
  EXTENDS, IMPLEMENTS, HAS_METHOD, ACCESSES) with confidence tiers.
- A resident index service serves search, explain and impact, with a freshness envelope.
  The old 800-file cap is gone; coverage is reported honestly instead.
- A BM25 code lane with hybrid RRF fusion, line-numbered snippets, explainable reasons and
  signed pagination cursors. Search refuses secret paths.

**Governed memory**
- Lifecycle states: supersede, retire, retract, purge, expiry, compare-and-swap edits and
  history.
- Provenance binding, evidence-bound votes, an owner-distinct quorum policy, and
  redaction of secrets on ingest.
- Recall v2 adds:
  - deterministic ranking with reasons;
  - filters and progressive disclosure;
  - `max_chars` budgets and signed cursors;
  - verification-queue views;
  - suppression of entries already shown to the session, with bounded memory.
- A human-approval surface:
  - `xmustard-ops approve|reject|queue`;
  - merge-approval attestations bound to a reviewed diff and its base (`xmustard-ops review gate --base`);
  - MCP elicitation where the client supports it.
- An injection-safety policy: an instruction-pattern scan and data framing on injected
  content, and quarantine for content derived from untrusted captures.

**Evidence, failures and grounding**
- Evidence reducers per tool family, with recoverable handles and search in the original.
- `why_failed` works in the core product from an evidence handle or a pasted log. Outcomes
  are stored in govstore and feed `ground.recent_failed_runs`. Command mode is **off by
  default**: it needs an operator opt-in (`XMUSTARD_WHY_FAILED_COMMANDS=1`) and an admin
  token. Once enabled, it is trusted host-code execution, not a sandbox.
- A governed automatic index baseline with history. Change tracking is bounded and reports
  `unknown` instead of 0 on errors.

**Security**
- Roles and route gates, and an exposure posture with a core-only default.
- Scoped workspace auto-registration.
- A shared redaction library.

**Integrations, evaluation and CI**
- The Pi adapter now covers built-in tools, masking and custom compaction.
- `xmustard-eval` outcome executor.
- Budget gate v2, the retrieval gate and the CI workflow.

## Measured on the release commit (Linux x86_64 build box)

- Full backend suites pass (all cargo tests; all 13 Go packages); clippy reports 6 warnings.
- `cargo build --locked`, `make bench-test` (74 tests) and the Pi check (44 tests) pass.
- The retrieval gate passes, 21 of 21 checks.
- Budget gate v2 (`--suite ci`) passes. Process-tree peaks: 70.5 MiB for the frozen v1
  workload over the stdio shim, and 68.8 MiB for 2 agents through `xmustard-relay`. The
  line is 95.4 MiB.

## Install

**Prebuilt binaries**, for macOS arm64 and Linux x86_64, are attached to the release. Each
archive holds:
- `xmustard-api`, `xmustard-mcp` and `xmustard-ops`;
- `xmustard-core` and `xmustard-relay`.

To install one:
1. Check the archive against its `.sha256` file.
2. Put the binaries on `PATH`, or point `XMUSTARD_CORE_BIN` at `xmustard-core`.
3. The macOS binaries are not signed, so clear the quarantine flag after download:
   `xattr -d com.apple.quarantine xmustard-*`.

The Linux binaries were built on Ubuntu 26.04. `xmustard-core` needs glibc 2.39 or newer
(Ubuntu 24.04+ or Debian 13+); on older systems, build from source.

**From source** (Go 1.26, Rust stable): `make build`.

**Homebrew**: the formula in `packaging/homebrew/xmustard.rb` builds this tag from source.

## Known limits

- `README.md` and `docs/STATUS.md` predate parts of this release. These notes and
  the build plan's implementation records are current.
- Runtime data files under `backend/data` are still tracked. Untracking them waits on the
  owner's approval.
- On macOS, one Rust memory test (the 100k-symbol resident graph) exceeds its line. Linux
  is the reference platform, and it passes there.
- Not in this release, still in progress:
  - the file watcher (WS-15);
  - the hook service and Claude Code plugin (WS-23);
  - the tag-triggered release workflow (WS-26);
  - the daemon lifecycle (WS-58);
  - wave 3.
