# WS-13: native stdio relay vs Go stdio shim, RSS per agent

Date: 2026-09-26. Branch `parity/ws-13`. Requirement PAR-RT-03 (relay ≤3 MiB).

## What was measured

Each stdio process was driven through the same session against one running
`xmustard-api` (core profile, open mode, one seeded workspace): `initialize`,
`notifications/initialized`, `tools/list`, then 20 `tools/call recall`. RSS was read
with `ps -o rss=` 300 ms after the last answer, before stdin closed. Three runs.

- Go shim: `api-go/cmd/xmustard-mcp` (`go build`, Go 1.26.1), pointed at the HTTP
  routes with `XMUSTARD_API_BASE`.
- Native relay: `rust-core/src/bin/xmustard-relay.rs` (`cargo build --release`,
  std only, 549 KiB binary), pointed at `/mcp` with `XMUSTARD_MCP_URL`.

Host: macOS (Darwin 27.0.0, arm64). The Linux build box was not measured for this
note; `TestNativeRelayAgainstAPI` logs the relay's RSS on every platform it runs on.

## Results

| Run | Go shim (KiB) | Native relay (KiB) | API (KiB) |
|-----|---------------|--------------------|-----------|
| 0   | 13,872        | 2,192              | 22,144    |
| 1   | 13,824        | 2,240              | 22,240    |
| 2   | 13,888        | 2,240              | 22,432    |

The relay stays under the 3 MiB target (2.1–2.2 MiB) and saves about 11.4 MiB per
stdio agent against the shim. A client configured with the URL runs no per-agent
process at all; its session costs the API process a Session (caches bounded by
`maxPathCache` and the evidence handle map) instead.

The integration test run recorded 1,984 KiB for the relay after initialize,
`tools/list` and one tool call.

## Gate v2 (`scripts/bench/rss_v2.sh`)

Same host, one run each, the 501-file generated fixture with 2 agents (28 tool calls).
Base is `feat/parity-v2` at 9e7cf78 (no `/mcp`, so its agents are Go shims); head is
this branch. The Rust core binary was the same for all three runs.

| Scenario | Transport | Owned-tree peak (MiB) | `mcp_access` peak (MiB) | `go_daemon` peak (MiB) |
|----------|-----------|-----------------------|-------------------------|------------------------|
| base `agents-2-small` | 2 Go stdio shims | 94.9 | 24.9 | 29.0 |
| head `agents-2-small` | Streamable HTTP | 63.7 | 0 (no process) | 28.8 |
| head `agents-2-relay` | 2 native relays | 68.0 | 3.9 | 28.8 |

Per agent, the access process falls from about 12.5 MiB (shim) to about 2 MiB
(relay), or to nothing over HTTP; the API's own peak does not move. The tree peak
also carries the per-call Rust cores (43–45 MiB here), so it varies more between
runs than the access line does.

```bash
scripts/bench/rss_v2.sh run --scenarios agents-2-small,agents-2-relay --out bench-out/ws13 \
  --core-bin rust-core/target/release/xmustard-core --relay-bin rust-core/target/release/xmustard-relay
git archive feat/parity-v2 | tar -x -C /tmp/base && scripts/bench/rss_v2.sh run \
  --scenarios agents-2-small --source-root /tmp/base --out bench-out/ws13-base --core-bin rust-core/target/release/xmustard-core
```

## Reproduce the per-process sample

```bash
cd api-go && go build -o /tmp/ws13/xmustard-api ./cmd/xmustard-api && go build -o /tmp/ws13/xmustard-mcp ./cmd/xmustard-mcp
cd ../rust-core && cargo build --release --bin xmustard-relay
# start the API, then drive each stdio process through initialize, tools/list and 20
# recall calls while stdin stays open, and read `ps -o rss= -p <pid>`
```

Not measured here: peak RSS under concurrent large results (the relay streams SSE
events line by line and holds one event at a time; the shim buffers up to 16 MiB per
response under its transient pool), and the API's added cost per HTTP session.
