## The resident service on real repositories

`scripts/bench/ws35_impact_rss.py BIN REPO OUT --rounds 2 --load sequential|overlapping`:
a clone of the repository is indexed, `xmustard-core serve --max-inflight=4` (one glibc
arena, as the Go supervisor starts it) answers rounds of impact, trace and search for
40 names from the index (240 queries), then one source file is edited and `index update`
lands while the rounds continue, so the service swaps snapshots under load. ps-RSS is
sampled every 50 ms; the figures are MiB above the service's RSS after `initialize`
(5.6 to 6.1 MiB).

Every run swapped once (generation 2) and stayed within the WS-14 line of 15 MiB. Impact
v2 costs +0.5 to +1.4 MiB here. Sequential p50 latency over the mixed queries fell from
2.17 / 2.23 / 0.58 ms to 0.46 / 0.60 / 0.40 ms, since the old impact listed every file
within four hops of the defining files; p95 (search and trace) is 85 to 240 ms both ways.

The base binary answers impact with the legacy file-level walk, so the two columns
measure different work: the head's answers are symbols with confidence, provenance and
a completeness envelope (`ws35-probes.txt`).

Sampled from `/proc` on the synthetic build (`ws35-build-peak.txt`), the heap is the same
(3.3 to 4.8 MiB) and the difference is the worker's own mapped image: 10.2 to 10.6 MiB of
the release binary at base and 11.4 to 11.7 at head (debug: 17.5 to 18.4 and 18.3 to 19.8).
A head variant that writes no drop sections measured the same, so the drops are not the
cause. The debug-build lines of this test and of the resident test are now guards (28 and
17 MiB) and the release build holds the 25 and 15 MiB lines; see the WS-35 record.
open-code-review's build is over the 25 MiB heavy line at base already.

## Probes

On cline, `Controller` has 180 direct dependents (CRITICAL); `buildApiHandler` has none
found because its callers import it through the tsconfig alias `@core/api`, which the
resolver does not read, and the answer says so (`unresolved_module`, a lower bound).
Every probe answer on these repositories is a lower bound: each has files that fell
back to the lexical extractor or parsed with errors. Import cycles: cline 14 components
(69 cycles, the largest 37 files), pi-mono 3 (4 cycles), open-code-review none.

## Caveats

- One machine, shared with other sessions' builds; RSS moved by about ±1 MiB between
  runs of the same binary. Benches ran one at a time.
- The real-repository runs use 40 probe names chosen by symbol id; half of them have no
  dependent under the default relation types (type members and interface properties
  are reached by USES and ACCESSES, which are opt-in).
