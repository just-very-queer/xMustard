# WS-17 scope/import resolver: transient, cost and precision — 2026-09-26

Status: **measured.** The Go and TS/JS resolver runs inside the `index build|update`
worker, in the heavy slot. On pi-mono it adds about 1 MiB to the worker's peak RSS. On
cline the change is within run-to-run noise, but cline already ran at the 25 MiB line
before this change and some runs now pass it. Full builds take 2–7 s longer; a one-file
update re-resolves one file. On the small precision fixture, every CALLS edge the
resolver emits matches the type checker's ground truth.

These are single-machine results under shared load, not a universal ceiling.

## Setup

- Binaries: `rust-core/target/release/xmustard-core` from `feat/parity-v2` at 9e7cf78
  (base, lexical edges only) and from `parity/ws-17` (resolver), both release builds.
- Machine: Apple M1, 8 CPUs, 8 GB, macOS 27.0. Other agents shared the machine. The
  same binary on the same input varied by up to ±0.7 MiB in peak RSS and 2× in wall
  time.
- Drivers:
  - `scripts/bench/index-rss.sh <bin> <repo> <work> 3`: three cold full builds
    (`--no-cache`), then a one-file edit with `index update`, then a noop update. It
    reports the `/usr/bin/time -l` maximum, which includes Git children.
  - `scripts/bench/worker-peak.py`: three alternating base/new full builds that sample
    the worker's own resident size every 1 ms.
- Fixtures: cline at ee59f81 and pi-mono at 5fd446c (Apache-2.0 and MIT; GitNexus is
  not used, per §2.4).

Raw records: `docs/benchmarks/evidence/2026-09-26/ws17-resolver.jsonl`.

## Heavy-slot transient

| Fixture | Binary | Worker peak RSS (own) | Footprint | `time -l` max RSS (full build) | Full build | 1-file update | Noop |
|---|---|---|---|---|---|---|---|
| cline | base | 23.3–24.0 MiB | 12.7–13.1 MiB | 23.9–24.0 MiB | 5.6–8.6 s | 18.7 MiB, 128 ms | 13.2 MiB, 80 ms |
| cline | ws-17 | 24.9–25.2 MiB | 13.4–13.8 MiB | 24.2–25.7 MiB | 9.9–14.3 s | 18.6 MiB, 150 ms | 13.4 MiB, 107 ms |
| pi-mono | base | 21.2–22.0 MiB | 12.3–13.1 MiB | 21.0–21.1 MiB | 5.5–5.7 s | 18.4 MiB, 125 ms | 12.3 MiB, 73 ms |
| pi-mono | ws-17 | 22.2–22.7 MiB | 13.1–14.4 MiB | 22.0–22.2 MiB | 8.3–9.0 s | 18.4 MiB, 98 ms | 12.2 MiB, 62 ms |

A resident-size timeline of one cline build puts the peak in the edge phase and the
final FTS `optimize`, as in WS-07. In a stage ablation on cline, three variants landed
in the same 24.2–25.2 MiB band: the resolver switched off, the resolver doing only its
deletes and file lookups, and the full resolver. On cline the resolver is not what sets
the peak; the run-to-run spread is as large as the difference. On pi-mono the full
resolver consistently adds 0.8–1.2 MiB.

The resolver started at +2.2 MiB on pi-mono. Three changes, each measured on pi-mono,
brought it to the numbers above:

| Change | Effect |
|---|---|
| Stream a file's references through one statement instead of collecting them; load only binding references eagerly; leave lexical-scanner words out. | 23.4 → 23.3 MiB (small: most files are small) |
| Global-tier cache holds symbol ids (`Global::One { id, file }`), not symbol rows, and at most 4,096 names. | 23.3 → 22.0–22.2 MiB |
| External bindings are counted but not stored in `resolve_drops`. | table size only |

**Open:** the Linux ps-RSS gate (`build_of_5000_files_has_no_file_cap_and_peaks_under_25_mib`)
was not re-run on the Linux box for this branch, because the box was unreachable. The
test passed locally on macOS. cline was 1.0–1.7 MiB under the line before WS-17 (worker peak)
and is now at it.

## Precision against type-checker ground truth (EVAL-09 input)

`rust-core/tests/resolve_fixtures.rs::precision_against_type_checker_ground_truth`
indexes `rust-core/tests/fixtures/resolve/precision/{go,ts}`. It compares the resolver's
CALLS edges (caller symbol → callee symbol) with ground truth from the type checkers
that gopls and tsserver use:

- Go: `go run truth/gen_go.go ../go` (go/types with the source importer);
- TS: `NODE_PATH="$(npm root -g)" node truth/gen_ts.cjs ../ts` (TypeScript checker).

| Fixture | Resolver CALLS | Ground truth | Correct | Precision | Recall |
|---|---|---|---|---|---|
| Go (2 packages, 3 files) | 16 | 17 | 16 | **1.000** | 0.941 |
| TS (3 files) | 14 | 15 | 14 | **1.000** | 0.933 |
| Overall | 30 | 32 | 30 | **1.000** | 0.938 |

Both misses are calls through a `range`/`for…of` loop variable whose element type the
resolver does not infer (`for _, s := range shapes { s.Area() }`). Both are recorded as
`receiver_untyped` drops, so the impact of `Shape.Area` reports a lower bound, not a
false exact answer. The fixtures are small, written for this purpose, and exercise the
shapes the resolver claims. This is not a precision estimate for real repositories;
EVAL-09 still needs a larger LSP/SCIP-labelled sample.
